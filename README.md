# Vibecoding Course Skills

Набор скиллов курса по вайб-кодингу, упакованный как плагин Claude Code.
Проводит проект по цепочке: **поиск идей → спецификация → инициализация → дизайн →
экраны → разработка по задачам → гигиена разработки → качество → выкладка →
аналитика**, плюс аккуратные коммиты.
Скиллы написаны на русском и объясняют каждый шаг человеческим языком, прежде чем
что-то делать.

## Что внутри

### Поиск идей — до спеки

| Скилл | Что делает |
|-------|------------|
| `ai-ideas` | Где ИИ поможет твоему бизнесу или жизни: свободный рассказ → карта из 1–2 самых больных процессов, разобранных до задач с числами → топ-идеи карточками с мини-проверкой у каждой + обязательный раздел «не стоит автоматизировать». Ни одной выдуманной цифры (пометки данные/допущение/веб), способ решения — самый дешёвый из подходящих, инструменты проверяются веб-поиском с датой. Работает в чате, файлов не пишет; идея-продукт уходит в `/create-spec` |

Черновик списка идей до показа человеку атакует отдельный агент-скептик
**`idea-skeptic`** (идёт в комплекте).

### Спецификация — план продукта до начала кода

| Скилл | Что делает |
|-------|------------|
| `create-spec` | Оркестратор: проводит идею через все три слоя спеки подряд с паузой на одобрение после каждого. Результат — три файла в `docs/spec/` |
| `spec-requirements` | Слой 1 — функциональные требования: «ЧТО продукт делает и ДЛЯ КОГО» → `docs/spec/01-functional-requirements.md` |
| `spec-architecture` | Слой 2 — техническая архитектура: «НА ЧЁМ собран, из каких компонентов» → `docs/spec/02-tech-architecture.md`. Здесь же единственный разговор про деньги: потолок трат, чем платить и что человек зафиксировал заранее |
| `spec-dev-architecture` | Слой 3 — девелоперская архитектура: «КАК запускать и как ИИ проверяет сам себя» → `docs/spec/03-dev-architecture.md` |
| `spec-user-flows` | Развёртка спеки в user flows: экраны, состояния, тексты ошибок → `docs/spec/04-user-flows.md` |
| `gather-context` | Скилл-интервьюер: задаёт вопросы по одному, к каждому предлагает рекомендованный ответ. Вызывается этапами спеки, работает и сам по себе |

Черновики каждого слоя проверяет отдельный агент-критик **`spec-critic`** (идёт в комплекте).

### Инициализация проекта

| Скилл | Что делает |
|-------|------------|
| `init-project` | Превращает спеку в живое рабочее место: проверка инструментов, git, каркас приложения, локальное окружение, `CLAUDE.md`, первый коммит. Безопасность — с первого дня |

### Дизайн и экраны

| Скилл | Что делает |
|-------|------------|
| `setup-ui` | Оркестратор дизайна: оба этапа подряд с паузой между ними |
| `choose-ui-kit` | Этап 1 — выбор и установка UI kit (против несогласованности интерфейса) |
| `customise-ui-kit` | Этап 2 — тема, шрифты, паспорт внешности `DESIGN.md` (против «ИИшного» дизайна) |
| `build-screens` | Сборка экранов по user flows на заглушках — рабочий UI раньше бэкенда, с UI-тестом на каждый поток |

### Разработка по задачам

| Скилл | Что делает |
|-------|------------|
| `create-dev-plan` | План разработки из спеки: очередь задач в `docs/tasks/` (одна задача — один присест агента, в плане не больше 15 задач, порядок задают только зависимости) плюс доска `board.md`. Повторный запуск — сверка плана с изменившейся спекой |
| `run-task` | Одна задача через полный цикл: исполнитель → независимый тестировщик → круг починок → автопроверки → приёмка человеком → коммит |
| `build-tasks` | Прогон всего плана: берёт задачи по одной через `run-task`, подряд и без лишних остановок; за прогон не больше 8 задач |

Цикл задачи опирается на двух агентов в комплекте: **`implementer`** (пишет код)
и **`task-verifier`** (независимо доказывает критерии приёмки).

### Гигиена разработки — прибраться между циклами

| Скилл | Что делает |
|-------|------------|
| `optimize` | Оркестратор гигиены одной командой: сначала доска (`groom-tasks`), затем тесты (`test-speed`); половины работают сами, финал — один общий отчёт и один «Что делать дальше» |
| `groom-tasks` | Укрупнение доски: сливает мелкие и однопричинные `todo`-задачи обратно под потолок в 15, не теряя ни одного критерия приёмки; план слияний всегда подтверждает человек |
| `test-speed` | Скорость тестов: обычный прогон ≤ 30 секунд и без e2e, всего e2e ≤ 10 — по одному на сценарий. Находит пожирателей времени и возвращает скорость, не ослабляя ни одной проверки; медленный продукт — задачей, а не заплаткой в тесте |

### Качество: рефакторинг, тесты, ручная проверка

| Скилл | Что делает |
|-------|------------|
| `refactor` | Улучшает структуру кода, не меняя поведения: чек-лист под стек проекта, маленькие шаги, зелёные тесты до и после |
| `test-audit` | Карта пробелов в автотестах: где нет теста вовсе, где только удачный сценарий, где тест-пустышка. Только читает и докладывает |
| `write-tests` | Пишет тест по пробелу или сценарию с обязательным red-first; найденный настоящий баг уходит баг-репортом, а не тихой правкой кода |
| `manual-test` | Сводка для ручного тестирования: как поднять, каким юзером зайти, что прокликать, как вызвать редкие состояния, что видели только автотесты |
| `health-check` | Обход по кругу: что из работавшего сломалось. Полный прогон проверок, ключевые сценарии живьём, ошибки за сутки и «тихие сроки» (истёкший ключ, кончившаяся квота, сертификат). Не чинит — заводит задачи `type: fix` |
| `simplify` | Ревизия готового продукта: что выкинуть, слить или упростить — фичи, шаги сценариев, код «на вырост», тексты. До 10 пронумерованных предложений с выигрышем и честной потерей; задачами становятся только номера, которые человек назвал сам |

### Выкладка

| Скилл | Что делает |
|-------|------------|
| `security-audit` | Аудит безопасности всего проекта: секреты, доступ к данным, деньги, конфигурация. Находки — тремя группами: сам в коде · через CLI с согласия · только человек в кабинете |
| `deps-audit` | Аудит зависимостей: уязвимости штатной командой экосистемы (серьёзность решает достижимость, а не балл сканера), заброшенные и лишние пакеты, lock-файл. Только читает — обновление идёт задачей через обычный цикл |
| `plan-deploy` | Выбор архитектуры выкладки: площадка, база, провайдер LLM, цена в месяц — с ценой каждого ответа и записью решения в слой 2 спеки |
| `deploy-audit` | Готовность к продакшн-деплою по чек-листу, до живого деплоя и смок-теста; финал — инструкция «🚀 Как задеплоить» под этот проект |

### Аналитика

| Скилл | Что делает |
|-------|------------|
| `plan-analytics` | Что и зачем измерять: сначала вопросы человека, потом метрики, потом события и инструменты. Результат — карта `docs/analytics.md` и план пробелов |
| `analytics-report` | Отчёт за период (прод по умолчанию, только чтение): здоровье · люди · ключевые действия · воронка · деньги — всегда с сравнением с прошлым периодом |

### Git

| Скилл | Что делает |
|-------|------------|
| `commit` | Аккуратные коммиты: только изменения сессии, несвязанные правки — раздельно, проверка на секреты и мусор до `git add`, план коммитов на подтверждение |

## Установка

Плагин ставится с GitHub через маркетплейс: маркетплейс подключается один раз,
затем из него ставится плагин.

### Шаг 1 — подключить маркетплейс

Внутри Claude Code:

```
/plugin marketplace add a-v-ershov/vibecoding_course_skills
```

### Шаг 2 — установить плагин

**Глобально** (для всех проектов на этой машине — это скоуп по умолчанию):

```
/plugin install vibecoding-course@vibecoding-course
```

**Только в текущий проект** — из терминала, с флагом `--scope`:

```bash
# в .claude/settings.json проекта — попадёт в git
claude plugin install vibecoding-course@vibecoding-course --scope project

# в .claude/settings.local.json — в git не попадёт
claude plugin install vibecoding-course@vibecoding-course --scope local
```

После установки перезапустите Claude Code. Скиллы появятся с префиксом `vibecoding-course:`.

### Управление

- `/plugin` — интерактивное меню: включить/выключить плагин, посмотреть состав.
- `claude plugin disable vibecoding-course` / `claude plugin enable vibecoding-course` — выключить и включить, не удаляя.
- `claude plugin uninstall vibecoding-course` — удалить.

## Использование

Идеи ещё нет — начни с нулевого шага: `/vibecoding-course:ai-ideas` разберёт твой
бизнес или личную рутину и предложит, где ИИ окупится; выбранная идея-продукт уходит
прямо в `create-spec`.

Полный путь нового проекта:

```
/vibecoding-course:create-spec «идея продукта в одном-двух предложениях»
/vibecoding-course:spec-user-flows
/vibecoding-course:init-project
/vibecoding-course:setup-ui
/vibecoding-course:build-screens
/vibecoding-course:create-dev-plan
/vibecoding-course:build-tasks
/vibecoding-course:refactor
/vibecoding-course:security-audit
/vibecoding-course:plan-deploy
/vibecoding-course:deploy-audit
/vibecoding-course:plan-analytics
```

Дальше — по поводу: `optimize` (прибраться между циклами: доска задач + скорость
тестов; половины доступны и по отдельности — `groom-tasks`, `test-speed`),
`test-audit` → `write-tests` (закрыть пробелы в тестах), `simplify` (что выкинуть
из готового продукта — решает человек по номерам), `deps-audit` (чужой код:
уязвимости и заброшенные пакеты), `manual-test` (сесть и прокликать руками),
`health-check` (обход после релиза или когда «опять что-то отвалилось» — находки
сразу становятся задачами), `analytics-report` (регулярный отчёт по выложенному
продукту), `run-task` (одна задача или баг вне плана), `commit` (сохранить работу).

### Деньги и ограничения

Инструменты подбираются по лестнице: сначала то, что уже есть и оплачено, потом
постоянно бесплатное, потом дешёвое, и только потом платное — платный вариант не
предлагается первым, если требования закрывает бесплатный. Про бюджет спрашивают
**один раз**, в `spec-architecture`; ответ живёт в разделе «Бюджет и ограничения по
инструментам» слоя 2 спеки и в `CLAUDE.md` проекта, и дальше его читают все скиллы,
которые что-то выбирают. Там же фиксируется собственное решение человека — конкретный
инструмент под компонент, «только бесплатное», «только то, что уже стоит»: к
зафиксированному альтернативы не предлагаются. Правило целиком —
`skills/_shared/constraints.md`.

Каждый скилл работает и сам по себе — можно запускать любой этап отдельно
(например, только `/vibecoding-course:commit` в существующем проекте).

## Обновление

Установленный плагин подхватывает изменения после повышения `version`
в `.claude-plugin/plugin.json` и `.claude-plugin/marketplace.json`:

```
/plugin marketplace update vibecoding-course
/plugin update vibecoding-course@vibecoding-course
```

И перезапустите Claude Code. Либо включите автообновление: `/plugin` →
**Marketplaces** → `vibecoding-course` → **Enable auto-update**.

Пока плагин активно дорабатывается, поле `version` можно убрать из обоих
манифестов — тогда новой версией считается каждый git-коммит, и bump не нужен.

## Структура репозитория

```
.claude-plugin/
  plugin.json        # манифест плагина
  marketplace.json   # манифест маркетплейса (репозиторий сам себе маркетплейс)
skills/              # 31 скилл, по папке на скилл (SKILL.md + references/)
  _shared/           # общие справочники (формат задач, бюджет и ограничения, формат отчёта), не скиллы
agents/
  spec-critic.md     # критик полноты спеки и плана задач
  idea-skeptic.md    # скептик списка ИИ-идей (для ai-ideas)
  implementer.md     # исполнитель одной задачи разработки
  task-verifier.md   # независимый тестировщик одной задачи
```
