# Этап 2 — Настройка UI kit («вкус задаём явно, а не надеемся на ИИ»)

## 📚 Объясни пользователю (перед началом, своими словами, 4–6 предложений)

Этот этап решает проблему ИИ-слопа: модель всегда сходится к среднему по интернету,
и получается узнаваемый «ИИшный» дизайн (фиолетово-синий градиент, шрифт Inter, тёмная тема со
свечением) — навайбкоженные сайты выглядят одинаково. Решение — задать визуальные параметры
**явно**. У UI kit есть **тема** — набор настраиваемых значений, **дизайн-токенов** («основной
цвет — такой, скругление — такое»): меняешь токены — весь продукт перекрашивается, а
согласованность UI-кита сохраняется. Источник вкуса — либо **готовая тема** сообщества (быстрый
путь — но галереи тем есть не у каждого UI-кита), либо **сайты-образцы**, которые нравятся человеку. Результат фиксируется в
`DESIGN.md` в корне проекта — «паспорте внешности» в открытом формате Google, по которому
ИИ собирает все следующие экраны.

## Порядок работы (скопируй чеклист в ответ и отмечай по ходу)

```
- [ ] 0. Вход: разбери аргумент (образцы / тема); определи UI kit проекта
- [ ] 1. Учебный блок: слоп, тема, токены, design.md
- [ ] 2. Разведка проекта (только чтение): текущая тема, шрифты, язык продукта
- [ ] 3. Витрина: где смотреть темы и образцы (ссылки) + поиск новых источников под UI-кит → ПАУЗА, человек выбирает сам
- [ ] 4. Разбор выбора: тема → прочитай токены; образцы → изучи браузером
- [ ] 5. Шрифты (обе ветки!): кириллица и лицензия; альтернативы со ссылками
- [ ] 6. Конфликты с текущей темой: таблицей, до изменений, жди решения
- [ ] 7. Паспорт внешности по формату Google → DESIGN.md в корне проекта + линтер
- [ ] 8. Применение: план изменений → подтверждение → применить → доказать скриншотом
- [ ] 9. Стоп: резюме
```

### 0. Вход

В аргументе могут быть: URL сайтов-образцов (к каждому — пометка, что с него брать: «отсюда —
цвета», «отсюда — шрифты и настроение»; без пометки = общее настроение) или имя/ссылка готовой
темы — выбор уже сделан, витрину шага 3 пропусти и иди сразу к шагу 4. Пусто → шаг 3.

Определи UI kit из кода: shadcn/ui — `components.json` + `components/ui/`; MUI, Mantine и др. —
по зависимостям. UI-кита нет → предложи сначала `/choose-ui-kit`; человек хочет без UI-кита →
работаем: токены будут просто CSS-переменными, DESIGN.md пишется так же.

### 2. Разведка проекта — только чтение

- **Текущая тема и где живут токены:** shadcn и Tailwind v4 — CSS-переменные в `globals.css`
  (блоки `:root` / `@theme`); Tailwind v3 — `theme.extend` в `tailwind.config`; MUI —
  `createTheme(...)`. Зафиксируй значения ключевых токенов и главное — **стандартные они или уже
  настроенные** (кто-то менял тему под себя).
- **Шрифты:** как подключены — `next/font`, `<link>` на Google Fonts, локальные `@font-face`.
- **Язык и характер продукта:** настоящие тексты интерфейса — в потоках
  (`docs/spec/04-user-flows.md`: заголовки, кнопки, ошибки), суть и аудитория — в слое 1
  (`docs/spec/01-functional-requirements.md`). Продукт на русском → в шаге 5 каждому шрифту
  обязательна проверка кириллицы. Длинные заголовки и плотные таблицы в потоках — сигнал
  к типографике: узкие шрифты и мелкие интервалы на таких экранах не работают.

### 3. Витрина и пауза — человек выбирает сам

Покажи одним сообщением, из чего выбирать, и остановись. Витрина состоит из трёх частей.

**Где смотреть готовые темы** — зависит от UI-кита; показывай только строки своего UI-кита и сверь
актуальность точечным поиском (галереи появляются и закрываются):

| UI-кит проекта | Где брать готовое |
|-------------|-------------------|
| shadcn/ui (веб, десктоп) | **tweakcn** — галерея тем сообщества: https://tweakcn.com/community; официальные инструменты на https://ui.shadcn.com — Typeset (подбор типографики) и Create (конструктор темы) |
| Mantine | **MantineHub** — галерея и конструктор тем: https://mantinehub.com |
| react-native-reusables (Expo) | токены совместимы с shadcn — значения темы с tweakcn переносятся в `global.css` вручную (объясни это человеку); плюс каталог готовых design.md (ниже) |
| Android (натив) | **Material Theme Builder** — человек даёт один цвет бренда, генератор отдаёт готовый код темы; плюс каталог готовых design.md (ниже) |
| iOS (натив) | галерей тем нет — только каталог готовых design.md (ниже) |
| MUI · чистый Tailwind · UI-кита нет | готовых галерей тем нет — остаются образцы и каталог design.md (ниже) |

**Каталоги готовых design.md** — паспорта внешности, уже снятые с известных продуктов:
выбирается продукт, похожий по характеру на свой, файл берётся за основу и адаптируется
(это основа, а не финал: палитру подгони под бренд, шрифты — обязательно через фильтр шага 5):

- **веб** — https://styles.refero.design/ — 2000+ design.md известных сайтов
  (Linear, Notion, Apple…); плюс https://github.com/nexu-io/open-design/tree/main/design-systems —
  150 дизайн-систем известных брендов (Linear, Stripe, Tesla…) в формате DESIGN.md,
  лицензия Apache-2.0;
- **мобильные приложения** — https://github.com/Meliwat/awesome-ios-design-md — 200 приложений
  по категориям (финансы, фитнес, соцсети…), каждый в четырёх вариантах: framework-neutral,
  SwiftUI, Expo/React Native, Jetpack Compose — вариант бери под стек проекта.

**Где смотреть сайты-образцы** (если готовой темы не хочется или её нет): галереи хороших
сайтов — Land-book (https://land-book.com), Godly (https://godly.website), siteInspire
(https://www.siteinspire.com), Mobbin (https://mobbin.com — 600k+ скриншотов сайтов и
мобильных приложений; бесплатно — ограниченный просмотр, полный доступ платный) — или просто
сайты, которыми человек пользуется и которые ему нравятся. Для мобильного проекта образцами
работают и веб-сайты (переносится вкус: палитра, типографика, настроение — не вёрстка),
и скриншоты любимых приложений (Mobbin здесь особенно кстати).

**Поиск свежих источников под UI-кит.** Перед показом витрины сделай 1–2 точечных веб-поиска
под UI-кит проекта («<UI-кит> themes gallery», «темы для <UI-кит>»): галереи появляются и закрываются,
и могло появиться что-то новое и хорошее. Нашёлся живой источник, которого нет в таблице, —
добавь его в витрину со ссылкой и одной строкой, что это. Конкретные темы не рекомендуй и
браузером на этом шаге ничего не открывай — только поиск: смотреть и выбирать будет сам человек.

**И остановись — жёсткая пауза.** Скажи: посмотри сам и возвращайся с выбором — имя/ссылка
темы, design.md из каталога или 2–3 сайта-образца (к каждому — что с него брать: цвета,
шрифты, настроение; «просто нравится» — тоже ответ). Не выбирай за человека и не продолжай,
пока он не вернулся с выбором. Человек явно просит «выбери сам» → только тогда открой галерею,
выбери тему под характер продукта из слоя 1 и скажи об этом прямо.

### 4. Разбор выбора

**Вернулся с готовой темой** (или design.md из каталога) → **прочитай её до применения**:
палитру, шрифты, радиусы (registry-JSON темы, страница темы или файл каталога). Из каталога —
это основа, а не финал: палитру подгони под бренд продукта. Шрифты пойдут в фильтр шага 5,
значения — в DESIGN.md шага 7.

**Вернулся с сайтами-образцами** → открой каждый браузером (браузер-инструмент, если доступен):
сними скриншот — настроение видно только глазами — и вытащи конкретику из стилей: шрифты
(`font-family`), основные цвета (фон, текст, акцент), радиусы, плотность. Браузера нет → скачай
HTML/CSS (WebFetch) и ищи то же в коде. По каждому сайту — 3–5 строк наблюдений и что берём
(по пометке человека). Скриншоты приложений от человека изучай глазами так же, как сайты.

💡 Поясни: мы берём **систему** — цвета, шрифты, ритм, характер, — а не копируем сайт.
Логотипы, иллюстрации, тексты и узнаваемую айдентику чужого бренда не переносим.

### 5. Шрифты — кириллица и лицензия (обе ветки, без исключений)

Готовые темы собраны западным сообществом и часто тянут шрифты **без кириллицы** — на
английском демо тема выглядит отлично, а на русском продукте шрифт молча подменится системным,
и настроение темы пропадёт. Поэтому фильтр проходят все шрифты: и из готовой темы, и с образцов.

**Кириллица.** Проверь: на Google Fonts открой страницу шрифта, в предпросмотре набери русскую
панграмму («Съешь ещё этих мягких французских булок») и проверь Cyrillic в списке языков;
у платных фаундри — раздел languages/glyphs. Кириллицы нет → подбери 1–2 альтернативы **того же
характера** (гротеск к гротеску, антиква к антикве — объясни термин одной строкой) с кириллицей
и прямыми ссылками; выбор — за человеком.

**Лицензия.** Google Fonts и лицензия SIL OFL — свободные; шрифт продаётся у фаундри (Klim,
Grilli Type, Commercial Type…) → платный. Платный → предупреди **до любых решений**, почему
«просто скачать» — плохая идея: шрифт юридически — программа, фаундри автоматически находят свои
шрифты на чужих сайтах и присылают претензию со счётом (файл веб-шрифта видит каждый посетитель);
«бесплатные» сборники часто пиратские и битые; для сайта нужна отдельная веб-лицензия. Выбор:
купить лицензию (ссылка и порядок цены) или бесплатная альтернатива того же характера —
рекомендация по умолчанию. Загляни в слой 2 спеки, раздел «Бюджет и ограничения по
инструментам»: потолок 0 ₽ — покупку лицензии даже не предлагай, сразу подбирай бесплатную
альтернативу и скажи, что платный вариант не рассматривался из-за бюджета.

Знания о шрифтах устаревают → подтверди альтернативы парой точечных поисков: шрифт существует,
бесплатен, кириллица на месте. Замена фиксируется в DESIGN.md одной строкой:
«в теме/на образце X, заменён на Y: нет кириллицы / платный».

### 6. Конфликты с текущей темой — до изменений

Разведка показала настроенную тему (значения отличаются от стандартных), а выбранное предлагает
другое → **остановись и покажи конфликты таблицей**: токен · сейчас · станет. Объясни
последствие: DESIGN.md станет новым правилом вида, и экраны под старую тему могут «поплыть».
Жди решения по каждому конфликту: заменить / оставить / смешать. Конфликтов нет — скажи одной
строкой и иди дальше.

### 7. Паспорт внешности — DESIGN.md в корне проекта

Файл пишется по открытой спецификации Google design.md —
https://github.com/google-labs-code/design.md. По ней имя файла — `DESIGN.md`, место — **корень
проекта** (там его ищут и другие ИИ-инструменты, работающие с форматом). Устройство: YAML-токены
между `---` (name, description, colors, typography, rounded, spacing, components) + секции прозы
в фиксированном порядке — Overview, Colors, Typography, Layout, Elevation & Depth, Shapes,
Components, Do's and Don'ts. Каркас — в `references/template.md`; точную схему токенов сверь
со спецификацией (`npx @google/design.md spec` или репозиторий).

Каждое значение — с пометкой «откуда» (тема такая-то / сайт-образец / «уже было в проекте»)
прямо в прозе секции, каждый цвет и шрифт — в привязке к токену UI-кита (например, `--primary`
у shadcn). Решения человека из шагов 5–6 фиксируй как принятые: заменённый шрифт — одной
строкой в Typography, анти-слоп-запреты — в Do's and Don'ts.

Готовый файл прогони линтером спецификации — `npx @google/design.md lint` — это механическая
проверка структуры (команду сверь с репозиторием спецификации).

### 8. Применение — план → подтверждение → доказательство

Покажи компактный план: какие файлы изменятся (`globals.css`, подключение шрифтов через
`next/font`, установка темы) и чем. Команду установки готовой темы **сверь с актуальной
документацией** (tweakcn/shadcn — точечный поиск), не по памяти. **Применяй только после
подтверждения плана человеком.**

После применения докажи наблюдаемо: запусти проект, сними скриншот страницы (лучше до/после)
и покажи. Прогони автопроверки: мини-скилл проверок ищи в `.claude/skills/` по описанию
«линтер, типы, тесты» (`check`, `run-checks` или похоже), нет такого — линтер стека напрямую.

### 9. Стоп

Покажи резюме: палитра одной строкой, шрифты со статусами (кириллица ✅/заменён, лицензия),
конфликты и решения, что изменилось в коде. Скажи:

> Паспорт внешности готов → `DESIGN.md` в корне проекта, тема применена. Теперь каждый новый экран ИИ
> собирает из компонентов UI-кита по этому файлу. Передумаешь про вид — запусти `/customise-ui-kit`
> ещё раз с новой темой или образцами. Дальше по курсу — `/build-screens`: он соберёт экраны по
> карте потоков (`docs/spec/04-user-flows.md`) на заглушках, ещё до бэкенда.

## Правила сжатия вывода

- `DESIGN.md` — **не длиннее ~1,5 страниц**; компактная проза по секциям, пустое не пишем.
- Один токен — одна строка; без обзоров «а ещё бывает…» — только выбранное и «откуда».
- Шрифтов в системе — не больше двух (заголовки + текст); больше — попроси человека выбрать.

## Правила

- Разведка, чтение темы и изучение образцов — только чтение; код меняется в шаге 8 и только
  после подтверждения плана человеком.
- Готовую тему предлагай, только если для UI-кита проекта есть живой источник тем (таблица
  шага 3 + сверка поиском); источника нет → только образцы, тем не выдумывай.
- Выбор темы или образцов — всегда за человеком после самостоятельного просмотра (пауза
  шага 3); скилл выбирает сам только по явной просьбе.
- Браузер — только для изучения образцов (шаг 4) и скриншота-доказательства (шаг 8);
  в витрине шага 3 браузер не открывается — только веб-поиск.
- Шрифтовый фильтр (кириллица + лицензия) обязателен в обеих ветках; платный шрифт без купленной
  лицензии в DESIGN.md не попадает — только альтернатива или явная пометка «человек покупает».
- Вдохновляемся системой, не клонируем айдентику: логотипы, иллюстрации и тексты не переносим.
- Конфликты с настроенной темой показываются до изменений; решение — за человеком.
- Факты ищи сам (UI-кит, тема, язык продукта); у человека спрашивай только решения — с
  рекомендованным вариантом первым.
- Объясняй термины одной строкой простыми словами (тема, токен, гарнитура, гротеск/антиква,
  лицензия, кириллица) — аудитория часто не дизайнеры.
- Пиши просто: что шаг делает и зачем. Без художественных оборотов и отсылок
  («та самая беда», «как у всех», «лечим»).
- Ссылки на шрифты, темы и альтернативы — прямые и проверенные поиском, не по памяти.

## Язык

Отвечай, спрашивай и пиши документ на языке пользователя; определять не по чему (скилл вызван
без текста) — по умолчанию русский. Код, идентификаторы и имена токенов не переводятся.
