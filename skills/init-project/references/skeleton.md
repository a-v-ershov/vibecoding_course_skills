# Каркас и локальное окружение — подробности

Справочник к шагу 6 скилла init-project: генератор каркаса, локальное окружение слоя 3, запуск
и остановка одной командой, мини-скиллы и плагин `security-guidance`. Гигиена пакетов — в SKILL.md.

## Каркас, окружение, запуск и остановка

- **Кода нет** → создай каркас штатным генератором стека из слоя 2: для веба —
  `create-next-app` и подобные, для iOS — шаблон проекта Xcode, для Python — стандартная
  структура пакета. Генератор даёт общепринятую структуру — руками каркас не выдумывай.
  **Код есть** → ничего не пересоздавай, только донастрой недостающее.
- **В текущую папку и без вложенного `.git`.** Генератор не должен создавать собственный
  git-репозиторий: `git init` уже сделан шагом 5 (большинство генераторов видят внешний
  репозиторий и не создают свой), а если у генератора есть явный флаг — используй его
  (у `create-next-app` это `--disable-git`). Генератор отказывается работать в непустой
  папке (в проекте уже лежат `.claude/` или `.agents/`, `AGENTS.md`, `CLAUDE.md`, `docs/`) →
  сгенерируй во временную подпапку, перенеси её содержимое в корень проекта, подпапку
  удали. Перед первым коммитом убедись, что вложенного `.git` не появилось; появился →
  удали его (истории в нём нет, только автоматический коммит генератора).
- **Локальное окружение слоя 3:** локальные заменители облачных компонентов (например,
  локальная база в docker), seed-скрипт с тестовыми данными ровно из слоя 3,
  переключатель моков (включён по умолчанию) и место под заготовленные тестовые ответы.
  Сами моки внешних API наполняются на этапе разработки — вместе с кодом, который их зовёт.
- **Запуск одной командой** из слоя 3 — собери эту обёртку; она и есть главный вход в
  проект для человека и для ИИ. Для веба — например, `npm run dev:all` (база + сервер +
  seed); для iOS — сборка и запуск в симуляторе одной командой.
- **Остановка одной командой** — если запуск поднимает фоновые долгоживущие сервисы
  (веб-сервер, локальную базу в Docker, воркер очереди, эмулятор), собери парную обёртку,
  которая гасит их все разом и приводит окружение в чистое стоячее состояние, **не теряя
  данные** (это не сброс базы — для сброса есть отдельная команда). Она выручает, когда
  прерванный или задвоенный запуск (Ctrl-C не вовремя, два `dev` разом) оставил стек
  наполовину поднятым: полная остановка + повторный запуск распутывают это одной командой,
  без ручного отлова зависших процессов и контейнеров. Останавливать нечего (CLI-утилита,
  библиотека, разовая сборка без сервисов) → команду не делай, это твоё исключение.

## Мини-скиллы и «охранник»

- **Мини-скиллы слоя 3** → `.agents/skills/<имя>/SKILL.md` по шаблону из
  `references/templates.md`, а в `.claude/skills/<имя>` — симлинк на него, чтобы скилл видели
  и Codex, и Claude Code; симлинки недоступны — копия в обе папки (схема и запасной путь —
  раздел 4 `../../_shared/platforms.md`). Команду проверок продублируй в `AGENTS.md`.
  Полноценно рабочими делай те, чья команда уже существует (сброс окружения, прогон проверок); тем,
  кому нужен ещё не написанный код продукта (например, прогон полного сценария), — рабочий каркас с
  пометкой TODO: доделывается на этапе разработки.
- **По желанию, только в Claude Code — «охранник» за плечом ИИ:** официальный плагин
  `security-guidance` (https://claude.com/plugins/security-guidance). Объясни человеку простыми
  словами: пока ИИ пишет код, плагин в фоне просматривает каждую правку на типовые дыры безопасности
  — секрет, попавший в код, инъекции, небезопасную работу с данными — и предупреждает сразу, а не
  когда проект уже опубликован. Человек согласен → пусть выполнит `/plugin install
  security-guidance@claude-plugins-official` и при установке выберет область **«project»** — плагин
  включится только для этого проекта, не трогая остальные. В Codex этот пункт пропусти.
