# Вход, разведка, план, инструменты и проверка запуска — подробности

Справочник к шагам 0, 2, 3, 4 и 7 скилла init-project: что брать из спеки, что выяснить при
разведке, примеры строк плана, как быть с инструментом, который не работает, и что показать в
проверке запуска. «То же» в шаге 4 — как с инструментом, который не поставить самому (SKILL.md,
шаг 4).

## Шаг 0. Что брать из спеки

Прочитай все три слоя `docs/spec/`: слой 2 даёт стек, компоненты, секреты **и раздел «Бюджет и
ограничения по инструментам»** (потолок трат, чем человек платит, что он зафиксировал); слой 3 —
запуск одной командой, seed, локальные заменители и мини-скиллы; слой 1 — контекст (что вообще
строим). Стек берётся из слоя 2, каким бы он ни был: веб на Node.js, нативное iOS-приложение на
Swift, бот на Python — шаги скилла одни и те же, меняются только инструменты. Рабочие мелочи, на
которые спека не отвечает (имя пакета, порт, версия), — спроси по ходу одной строкой, не изобретай
молча.

## Шаг 0. Спеки нет — темы для вызова `gather-context`

Вызови `gather-context` с минимумом тем: стек и платформа (веб / мобильное / другое; фронтенд, бэкенд, база — что
из этого есть), внешние сервисы и их ключи, как запускать локально, что при проверках
заменяем заглушками.

## Шаг 2. Что выяснить при разведке

- **ОС и архитектура** (macOS / Linux / Windows, arm/x86) — от этого зависят команды
  установки и сама возможность стека (нативная iOS-разработка требует macOS с Xcode);
- **инструменты стека на месте?** Список выведи из слоёв 2–3, не из привычки: git — всегда;
  дальше по стеку — Node.js и Docker для веба, Xcode и его командные инструменты для iOS,
  Python для бота, и так далее. У каждого проверь и версию, и состояние (Docker может
  стоять, но демон не запущен — `docker info`); gh — есть ли и авторизован ли (`gh auth status`);
- **что уже есть в папке:** git-репозиторий? каркас кода (`package.json`, `*.xcodeproj`,
  `pyproject.toml`…)? `.gitignore`, `AGENTS.md`, `CLAUDE.md`, `.env.example`, `docs/`?

## Шаг 3. Примеры строк плана

Например: `supabase start` — «поднимает на твоём компьютере локальную копию базы данных, чтобы
проект работал без облака и бесплатно»; `.gitignore` — «список файлов, которые git не сохраняет:
мусор, сборка, секреты».

## Шаг 4. Инструмент стоит, но не работает; настройка не из командной строки

- Инструмент стоит, но не работает (демон Docker не запущен, Xcode без лицензии или без
  симуляторов) → попроси человека запустить/донастроить (или предложи команду) и дождись
  подтверждения.

- То же — с любым компонентом, который не настраивается из командной строки: веб-консоль
  сервиса, графический установщик, параметры в облаке. Дай короткую пошаговую инструкцию —
  что открыть, куда нажать, что ввести и что вернуть тебе (например, какой ключ положить
  в `.env`) — и продолжай только после результата.

## Шаг 7. Что проверять

- **приложение живо:** сайт — страница отвечает (скриншот через браузер, если доступен,
  иначе ответ сервера 200 с телом); нативное приложение — сборка прошла и приложение
  открылось в симуляторе (скриншот симулятора);
- **база жива и seed лёг** (если база есть в стеке) — покажи строку тестового пользователя
  запросом к базе;
- **мини-скиллы работают** — прогони сброс окружения и прогон проверок.
