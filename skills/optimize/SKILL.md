# Optimize — гигиена разработки одной командой

## 📚 Объясни пользователю (перед началом, своими словами, 4–6 предложений)

Разработка тухнет в двух предсказуемых местах, и оба портятся сами, без чьей-то ошибки.
Первое — **доска задач**: аудиты и просьбы «поправь ещё вот это» заводят задачи по одной,
и через пару недель вместо пятнадцати связных задач — сорок мелких, где каждая стоит полного
цикла проверки и приёмки. Второе — **тесты**: каждая задача добавляет своих, прогон дорожает
с минуты до пяти, и его тихо перестают запускать — а незапущенный тест не защищает ничем.
Этот скилл существует, чтобы «надо бы прибраться» было одной командой: он прогоняет два
этапных скилла по очереди — `groom-tasks` сольёт мелочь на доске, `test-speed` вернёт
прогону скорость — и сведёт их результаты в один отчёт. Всю работу делают они, каждый
со своим планом и твоим подтверждением; этот скилл только дирижирует.

## Твоя роль

Ты — дирижёр: ведёшь две половины по очереди и сводишь их отчёты. Всю содержательную работу
(размеры задач, план слияний, замеры, план ускорения) делают этапные скиллы — **не дублируй
их логику**: ни одного правила слияния и ни одного бюджета здесь нет, и сам ты ничего
не сливаешь и не ускоряешь.

## Порядок работы

```
- [ ] 0. Вход: что есть в проекте (доска? тесты?) + аргумент → что прогоняем
- [ ] 1. Учебный блок: два места, где разработка тухнет, и что сейчас будет
- [ ] 2. Половина 1: вызови скилл groom-tasks (пропуск — объяви одной строкой)
- [ ] 3. Половина 2: вызови скилл test-speed (пропуск — объяви одной строкой)
- [ ] 4. Итог: один общий отчёт + один блок «Что делать дальше»
```

### 0. Вход

Проверь, к чему проход вообще применим: есть ли доска (`docs/tasks/` непуста) и есть ли
тесты (папки тестов или конфиг раннера). Аргумент «задачи» или «тесты» сужает проход до
одной половины. Половина, чьего предмета в проекте нет, **пропускается с объявлением
одной строкой** — никогда молча. Делать нечего вовсе — так и скажи и остановись.

### 2–3. Две половины по очереди

Вызывай этапные скиллы через Skill tool: сначала **`groom-tasks`**, затем **`test-speed`**.
Порядок неслучайный: уборка доски дешёвая и её результат задаёт рамку отчёта, аудит тестов —
длинная половина. Каждый этапный скилл сам показывает свой план и сам ждёт подтверждения
человека — **уважай его паузы**: не отвечай «да» за человека и не подгоняй. Собери с каждого
короткую сводку: у доски — открытых было/стало, у тестов — секунды прогона было/стало и
сколько e2e.

### 4. Итог

Один общий отчёт по формату `skills/_shared/report-format.md` этого плагина: первой строкой —
итог обеих половин («доска 34 → 12 задач; прогон 96 с → 24 с»), затем по паре строк на
половину (что нашла и что изменила), что пропущено и почему. И **один** общий блок
«Что делать дальше»: пункты обеих половин вместе, без дублей, перенумерованные —
человек получает один список, а не два отчёта, которые надо сводить самому.
«Ничего» — валидный ответ.

## Правила

- **Дирижируй, не дублируй.** Правила слияния живут в `groom-tasks`, бюджеты — в
  `test-speed`; здесь не пересказывается ни то, ни другое, и сам скилл ничего не правит.
- **Подтверждения принадлежат этапным скиллам.** Их паузы не проскакиваются и «да» за
  человека не отвечается.
- **Пропуск объявляется** — одной строкой с причиной, никогда молча.
- **Сначала задачи, потом тесты** — дешёвая половина задаёт рамку, длинная идёт второй.
- **Один общий отчёт и один «Что делать дальше»** — списки половин сливаются и
  перенумеровываются (`skills/_shared/report-format.md` этого плагина).
- Отвечай на языке пользователя; определять не по чему (скилл вызван без текста) —
  по умолчанию русский. Код и идентификаторы не переводятся.
