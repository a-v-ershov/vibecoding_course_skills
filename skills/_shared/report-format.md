# Формат финального отчёта (общий файл)

Этот файл — общий контракт для скиллов курса, которые заканчивают работу отчётом. Правило,
из которого следуют все остальные: **отчёт читает человек, который не смотрел за работой**, —
и часто он не программист. Он должен понять результат с одного прочтения и без встречного
вопроса «и что мне теперь делать?».

Каждое правило ниже появилось не из вкуса, а из практики: отчёты бывали полными, точными —
и нечитаемыми. Длина, потраченная на то, на что человек не может повлиять, хоронит ту одну
строку, которая ему нужна. **Проще понять — важнее, чем полнее.**

## 1. Первой строкой — итог

Первая строка отчёта отвечает на вопрос «что случилось» или «что нашлось», а не «что я делал».
Вердикт — до истории: «Прогон тестов ускорен с 96 до 24 секунд, проверки не ослаблены», а не
«Сначала я изучил конфигурацию раннера…». Отчёт, который начинается с метода, похоронил свой
результат.

## 2. Детали — в документ, а не в чат

В чат идёт только то, что меняет следующий шаг человека. Всё остальное — полные таблицы,
сырые выводы команд, доказательства по каждому пункту — живёт в документе (`docs/reports/`,
файл задачи, спека), а отчёт даёт на него ссылку одной строкой. Документ — это запись,
отчёт — это брифинг; пересказывать документ в чате не нужно.

## 3. Без жаргона

Внутренние слова курса и стека (`blocked_by`, «карантин», «фикстура», advisory) в отчёте
переводятся в значение для читателя: не «3 задачи ушли в needs_human», а «3 задачи ждут
твоего решения — два круга починки не помогли». Термин допустим только там, где он —
якорь, по которому человек будет искать (имя файла, команда, номер задачи).

## 4. В конце — блок «Что делать дальше»

Финал каждого отчёта — блок с таким заголовком:

- нумерованный список, повелительное наклонение, одна строка на пункт;
- человеческим языком: что сделать и что это даст, а не внутренняя механика;
- пункт-команда называется явно: «запусти `/run-task T07` — починит красный тест оплаты»;
- **«ничего» — валидный ответ**, и он тоже пишется явно: «Ничего: доска в порядке,
  13 связных задач». Выдумывать пункты ради списка нельзя.

## 5. Цифры сходятся

Если отчёт называет числа — задач было/стало, секунды прогона, находки по группам, — они
должны сходиться между собой: группы в сумме дают итог, «было минус стало» равно заявленной
экономии. Число, которое не с чем сверить, вызывает недоверие ко всему отчёту.

## Скелет хорошего отчёта

```markdown
<Итог одной строкой: что случилось / что нашлось.>

<2–5 строк или компактная таблица: главное, с числами, которые сходятся.>
<Ссылка на документ с деталями, если он есть.>
<Чего проверить не удалось — честно, одной строкой.>

## Что делать дальше
1. <действие — и что оно даст>
2. <действие — и что оно даст>
```

## Язык

Отчёт пишется на языке пользователя; определять не по чему — по умолчанию русский.
Код, команды, идентификаторы, пути и номера задач не переводятся.
