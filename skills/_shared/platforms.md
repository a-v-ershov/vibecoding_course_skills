# Claude Code и Codex: как одни и те же шаги выглядят в разных инструментах (общий файл)

Этот файл — общий контракт для всех скиллов и агентов плагина. Скиллы пишутся **нейтрально
к инструменту**: «запусти агента `spec-critic`», «задай закрытый вопрос с вариантами»,
«`AGENTS.md` проекта». Как именно это сделать в Claude Code и в OpenAI Codex — записано
здесь, один раз, а не в каждом скилле.

Зачем это вообще. Плагин ставится и в Claude Code, и в Codex: формат скиллов у них общий
(папка со `SKILL.md`), а инструменты, файлы правил и способ запуска агентов — разные. Если
каждый скилл будет упоминать конкретный инструмент, в другом агенте он сломается на первом же
шаге. Поэтому различия собраны в одном месте.

Узнать, где работаешь, просто: ты знаешь свои инструменты. Есть `AskUserQuestion` и агенты
по `subagent_type` — это Claude Code; есть `spawn_agent` / `request_user_input` — это Codex.
Ни то ни другое — смотри строку «Запасной путь» в каждом разделе.

## 1. Агент плагина

Скилл пишет: «запусти агента **`<имя>`**». Агенты плагина лежат в `agents/<имя>.md`
этого плагина (`implementer`, `task-verifier`, `spec-critic`, `idea-skeptic`).

**Это явное указание скилла запустить отдельного субагента** — именно та «просьба скилла
о субагенте», после которой правила инструмента разрешают его запуск. Не заменяй субагента
проверкой своими силами, пока инструмент запуска доступен: независимый взгляд и есть смысл шага.

| | Как запустить | Как продолжить того же агента |
|---|---|---|
| **Claude Code** | Agent tool, `subagent_type: <имя>` — агент зарегистрирован плагином | продолжить диалог с ним (SendMessage по его id), не создавая нового |
| **Codex** | плагины Codex агентов не поставляют, поэтому — обычный субагент: `spawn_agent` с `fork_turns: "none"` (без твоей истории — иначе субагент не независим), первой строкой задания: «Прочитай `<путь к плагину>/agents/<имя>.md` и работай строго по нему; frontmatter — описание роли, `tools:` — список того, чем тебе можно пользоваться». Дальше — само задание из скилла. Итог агента дождись через `wait_agent` | `followup_task` тому же агенту (по его имени из `spawn_agent`), а не новый `spawn_agent` |
| **Запасной путь** | инструмента запуска субагентов нет или вызов вернул ошибку — прогони чек-лист агента сам **отдельным заходом**, начав с чтения его файла, и честно скажи человеку, что независимой проверки не было | — |

Правила, общие для обоих инструментов:

- **Свежий агент — значит без твоего контекста.** Передавай только то, что велит скилл (номер
  задачи, путь к файлу, черновик), и не пересказывай ход своей работы — независимость и есть
  смысл отдельного агента.
- **Ограничения из `tools:` соблюдаются, даже если инструмент их не навязывает.** `spec-critic`
  только читает файлы; `idea-skeptic` только читает и ищет в вебе. В Codex frontmatter агента
  никто не применяет — ограничение держится на инструкции, поэтому оно продублировано в тексте
  каждого агента.
- Путь к плагину — папка, в которой лежит этот файл, на два уровня выше (`skills/_shared/` →
  корень плагина). Агенты — в `agents/` корня.

## 2. Закрытый вопрос с вариантами

Скилл пишет: «задай закрытым вопросом с вариантами» (2–4 варианта, рекомендованный первым
с пометкой «(Рекомендую)», несколько созревших развилок можно одним пакетом).

| | Как задать |
|---|---|
| **Claude Code** | инструмент `AskUserQuestion` (до 4 вопросов за раз) |
| **Codex** | инструмент `request_user_input`, если он доступен в текущем режиме |
| **Запасной путь** | обычным сообщением: вопрос, под ним нумерованные варианты (рекомендованный — первым, с пометкой), в конце «ответь номером или своими словами» — и **жди ответа**, не продолжай за человека |

Правило, которое не зависит от инструмента: весь контекст, нужный для ответа, — **внутри
самого вопроса**. В некоторых интерфейсах (например, расширения для VSCode) текст перед окном
вопроса не виден, пока окно открыто.

## 3. Файл правил проекта

Скилл пишет: «`AGENTS.md` проекта».

- **Правила проекта живут в `AGENTS.md`** в корне — его читает Codex и большинство других
  ИИ-агентов.
- **`CLAUDE.md` — одна строка `@AGENTS.md`**: так Claude Code подтягивает тот же файл, и проект
  одинаково работает в обоих инструментах. Содержимое в `CLAUDE.md` не дублируется.
- **Старый проект, где правила только в `CLAUDE.md`**, — читай его как файл правил. Переносить
  содержимое в `AGENTS.md` можно только с согласия человека (это делает `init-project`).
- Дополнять — не затирать: в существующий файл правил новое дописывается, старое остаётся.

## 4. Мини-скиллы проекта

Мини-скиллы слоя 3 (команда проверок «линтер, типы, тесты», запуск, сброс данных) — это скиллы
самого проекта, не плагина.

- **Искать в обеих папках:** `.claude/skills/` (Claude Code) и `.agents/skills/` (Codex).
  Опознаются по описанию, а не по имени — в разных проектах имена разные.
- **Создавать там, откуда читает текущий инструмент:** в Claude Code — `.claude/skills/<имя>/`,
  в Codex — `.agents/skills/<имя>/`.
- **Сама команда проверок дублируется в `AGENTS.md`** (раздел «Команды»): так её найдёт и
  другой инструмент, и человек.

## 5. Веб-поиск

Нужен скиллам, которые проверяют цены, тарифы и сервисы (`ai-ideas`, `plan-deploy`,
`plan-analytics`, `deps-audit`), и агенту `idea-skeptic`.

| | Чем |
|---|---|
| **Claude Code** | `WebSearch`, `WebFetch` |
| **Codex** | встроенный веб-поиск (если он включён в настройках) |
| **Запасной путь** | поиска нет — так и скажи, а факты, которые надо было проверить, пометь как непроверенные; выдумывать цены и тарифы нельзя |

## 6. Постоянная память агента

Некоторые скиллы просят «закрепить правило и в памяти» (например, правило git из
`init-project`). Если у текущего инструмента есть постоянная память между сессиями — сохрани
туда отдельной заметкой. Нет — достаточно `AGENTS.md`: он читается в каждой сессии.

## 7. Вызов скиллов и сжатие контекста

- Человек вызывает скилл: в Claude Code — `/vibecoding-course:<скилл>` (или `/<скилл>`),
  в Codex — `$vibecoding-course:<скилл>`. В текстах скиллов команды записаны как `/<скилл>` —
  в Codex это значит `$vibecoding-course:<скилл>`; другой скилл плагина ты вызываешь сам,
  прочитав его `SKILL.md` (папка `skills/<скилл>/` этого плагина).
- Сжать контекст длинной сессии — `/compact` в обоих инструментах.
- Ревью текущего диффа на безопасность — `/security-review` в Claude Code, `/review` в Codex
  (с просьбой смотреть на безопасность).
