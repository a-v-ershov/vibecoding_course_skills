# Справочник: чем измерять продукт

**Собрано: июль 2026** (по знанию модели, без сверки с первоисточниками). Это **заготовка,
а не список разрешённых решений**: тарифы, бесплатные лимиты и сама доступность сервисов
меняются каждые несколько месяцев. Перед показом человеку **сверь веб-поиском те 2–3 варианта,
что реально попали в шорт-лист** (живы ли, что в бесплатном плане, доступны ли из России), и
поищи, не появилось ли нового. Справочник разошёлся с вебом — верь вебу и скажи об этом вслух.

Варианты по умолчанию ниже — **осознанно мнения, а не «на выбор всё подряд»**: у маленького
продукта должен быть один понятный первый шаг, а не десять равноправных логотипов. Но выбор
по умолчанию — это отправная точка, которую подтверждают три оси; выбирай не по привычке,
а по ним:

- **Где происходит действие** — на **бэкенде** (оставляет строку в базе: регистрация, генерация,
  оплата) или в **браузере/приложении** (видно только клиентским счётчиком: куда кликнул, где
  закрыл, как прошёл экран). Бэкенд-действия не требуют стороннего сервиса вообще — семейство 1.
- **Кто пользователи** — **из России без VPN** или **международная аудитория**. От этого зависит,
  какой сервис у человека вообще загрузится и куда по закону можно отдавать данные. Для российского
  продукта «работает без VPN» — часто главное обещание, а не мелочь: сервис, чей скрипт не грузится
  из России, не просто не считает — он тормозит страницу.
- **Площадка** — **сайт** или **мобильное приложение**. Инструменты у них разные, счётчик для сайта
  в приложении не работает.

Порядок семейств — от «уже есть у тебя» к «отдельный сервис». Идти сверху вниз: следующее
семейство подключается, только когда предыдущее не отвечает на вопрос человека.

## 1. Своя база и свои логи — источник по умолчанию для бэкенда

Ничего не ставится, данные никуда не уезжают, стоимость ноль. **Выбор по умолчанию для любой
метрики, действие которой оставляет строку в базе.** Воронку «зарегистрировался → сделал
ключевое действие → оплатил тариф» целиком достаёт один SQL-запрос к своим же таблицам —
сторонний счётчик для неё не нужен, нужен скрипт (этим и занимается `/analytics-report`).

| Что даёт | Чего не даёт |
|---|---|
| Сколько людей, сколько действий, воронка по своим таблицам, деньги, любые срезы запросом | Поведение внутри страницы (куда кликают, где закрывают), запись сессии, готовые графики, источники трафика |

Чтобы это работало, нужны три вещи (они же — типовые пробелы):

- **дата и владелец у ключевых действий** — `created_at` и `user_id` в таблицах: без них нельзя
  ни срез по периоду, ни «сколько разных людей»;
- **таблица событий** — одна таблица вида `(id, время, пользователь, событие, свойства JSON)`
  для действий, которые не оставляют своей записи (открыл экран, нажал кнопку, увидел ошибку);
- **структурированные логи** — уровень (`info`/`warn`/`error`), время, идентификатор пользователя
  и запроса в каждой строке. Простой текст «что-то пошло не так» посчитать нельзя.

Отдельно: **логи платформы деплоя** — они уже есть и ничего не стоят, но обычно хранятся
недолго (часы-дни) и живут только в кабинете/CLI платформы. Для «что упало вчера» хватает,
для «сравнить с прошлым месяцем» — нет.

## 2. Готовый дашборд поверх своей базы

Когда цифры из пункта 1 есть, но лень каждый раз писать запрос.

| Инструмент | Особенность |
|---|---|
| Metabase | вопросы мышкой без SQL, self-hosted бесплатно, есть облако |
| Grafana | графики и алерты, умеет и метрики, и логи |
| Встроенный SQL-редактор платформы базы | ноль настройки, но без сохранённых дашбордов |

Замечание для этого класса: дашборд ходит в **боевую** базу — только на чтение и лучше
отдельным пользователем базы с правами только `SELECT`.

## 3. Продуктовая аналитика фронтенда — поведение людей

Нужна, когда вопросы становятся про **как именно** пользуются: порядок шагов, где бросают,
запись сессии (реплей / вебвизор), карты кликов, источники трафика — то, чего в базе нет.
Это уже **отправка данных твоих пользователей стороннему подрядчику**, поэтому выбор начинается
с оси «кто пользователи», а не с тарифа.

### Веб-сайт

| Ситуация | По умолчанию | Почему |
|---|---|---|
| **Аудитория РФ, без VPN** | **Яндекс.Метрика** | бесплатна, грузится из России, **Вебвизор** (запись сессий) и карты кликов из коробки — то, за что в других местах доплачивают; цели и JS-события (`ym(id,'reachGoal',…)`) настраиваются на месте. Данные — у Яндекса |
| **Экосистема Google / международная аудитория** | **GA4 + Microsoft Clarity** | GA4 бесплатна и стандарт рынка, но **записи сессий у неё нет** → рядом ставят Clarity (бесплатный вебвизор и тепловые карты от Microsoft). Оба — данные наружу, из России нестабильны |
| **Нужен «продуктовый максимум» в одном** | **PostHog** | реплей + воронки + флаги фич + A/B в одном инструменте. Но честно: хостинг заграничный, для РФ-пользователей спорно, новичку сложнее — это **продвинутый вариант**, а не первый выбор |

### Мобильное приложение

Счётчик для сайта в приложении не работает — тут свои SDK. Часто аналитика приложения **сразу
включает отчёты о падениях**, и отдельный сборщик ошибок (семейство 4) уже не нужен.

| Ситуация | По умолчанию | Почему |
|---|---|---|
| **Аудитория РФ** | **Яндекс AppMetrica** | бесплатна без лимита событий, аналитика + отчёты о падениях/зависаниях в одном, доступна из России |
| **Международная** | **Firebase** (Google Analytics + Crashlytics) | стандартный мобильный стек Google: события, воронки, ретеншн и краши вместе |
| **«Всё в одном»** | **PostHog** (мобильные SDK) | тот же продвинутый вариант, что и на вебе, с теми же оговорками про заграничный хостинг |

Общее правило семейства: не клади в события почту, имя, содержимое, платёжные реквизиты —
хватает идентификатора и факта действия. И **проверь доступность выбранного сервиса из России
до установки, а не после**.

## 4. Сборщик ошибок — техническое здоровье (фронт + бэк)

Отдельный класс: не «сколько людей», а «что сломалось, у кого и с каким стеком вызовов»,
группировка одинаковых, алерты. Один сервис обычно ловит и фронтенд, и бэкенд.

| Ситуация | По умолчанию | Почему |
|---|---|---|
| **Международный стандарт** | **Sentry** | мировой лидер в ловле ошибок, и на фронте, и на бэке, куча SDK. Но **доступ из России ограничен/заблокирован** — на РФ-проде без обходов не работает |
| **Аудитория/хостинг в РФ** | **Hawk** (hawk.so) | российская альтернатива Sentry: тот же смысл (фронт + бэк, группировка, стектрейсы), доступна из России |
| **Данные нельзя отдавать наружу** | **GlitchTip** (self-hosted) | лёгкая self-hosted альтернатива, совместима с клиентами Sentry — UX Sentry без отправки данных подрядчику |
| **Не хочу отдельный сервис** | уровни в логах + ловля необработанных ошибок | ноль стоимости, но группировать и искать придётся руками; для мобилок краши обычно уже ловит аналитика (AppMetrica/Crashlytics) |

Для только что выложенного продукта это обычно **самое полезное первое вложение**: пока
падает, продуктовые метрики всё равно не о чем.

## 5. Хранилище логов

Нужно, когда логов платформы не хватает: хранятся мало, искать неудобно, нет алертов.
Семейство: Better Stack, Axiom, Grafana Loki, ELK. Все берут деньги за объём — прежде чем
подключать, посмотри, сколько логов продукт вообще пишет в сутки.

## Как выбирать (короткий алгоритм)

**Нулевой фильтр поверх всего — откуда пользователи.** Аудитория из России без VPN отсекает
Sentry и делает PostHog спорным раньше, чем ты сравнишь тарифы: сначала «загрузится ли сервис
у моих людей и можно ли отдавать туда данные», потом «сколько событий в бесплатном плане».

1. Действие происходит на бэкенде и оставляет строку в базе? → семейство 1, **пиши SQL-скрипт,
   ничего не ставим**.
2. Вопрос про «что падает»? → сначала уровни в логах, потом сборщик ошибок (семейство 4):
   РФ → **Hawk**, международный → **Sentry**.
3. Вопрос про поведение в браузере/приложении (порядок кликов, где закрывают, запись сессии)? →
   продуктовая аналитика (семейство 3): веб РФ → **Метрика**, Google/международный →
   **GA4 + Clarity**, продвинутый → **PostHog**; мобилка → **AppMetrica** (РФ) / **Firebase**.
4. Цифры из базы есть, но смотреть неудобно? → семейство 2.
5. Логов не хватает по глубине или поиску? → семейство 5.
