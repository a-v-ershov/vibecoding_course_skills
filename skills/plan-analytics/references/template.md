# Шаблон карты аналитики — `docs/analytics.md`

Заполняется скиллом `plan-analytics`, читается скиллом `analytics-report`. Держи компактным:
это рабочая карта, а не отчёт. Всё конкретное — имена таблиц, полей, команд — из настоящего
проекта; выдуманных не бывает. Раздел, для которого в проекте нет содержания (нет платежей,
нет фоновых задач), просто не пиши.

---

```markdown
# Аналитика продукта

Обновлено: <дата> · Планировал: /plan-analytics · Отчёты: /analytics-report

## 1. Вопросы, на которые отвечаем

| Вопрос человека | Метрика | Что сделаю, узнав ответ |
|---|---|---|
| Живой ли продукт прямо сейчас? | ошибок за сутки, упавших фоновых задач | чиню в тот же день |
| Люди вообще доходят до результата? | дошли до <ключевое действие> / зарегистрировались | упрощаю самый узкий шаг |
| Не растёт ли расход быстрее пользы? | ₽ на внешние API / оплат за период | режу лимит или цену |

Правило: строка, у которой третья колонка пустая, из карты удаляется.

## 2. Ключевые действия (события)

| Действие | Где фиксируется сейчас | Как достать | Есть? |
|---|---|---|---|
| Регистрация | `users` (`created_at`) | SQL по дате | ✅ |
| <главное действие продукта> | `<таблица>` (`status`, `created_at`) | SQL по дате и статусу | ✅ |
| Оплата | `payments` (`status='succeeded'`) | SQL по дате | ✅ |
| <клик/экран во фронтенде> | <продуктовая аналитика: Метрика-цель / событие GA4> | API сервиса за период | ⚠️ не подключено |
| Ошибка у пользователя | <сборщик ошибок: Hawk / Sentry> или лог уровня error | API сборщика / лог прода по уровню | ⚠️ логи без уровней |

## 3. Воронка

Шаги по порядку, от входа до ценности. На каждом — как считается «дошёл».

1. Зашёл на страницу → <источник>
2. Зарегистрировался → `users`
3. Запустил <главное действие> → `<таблица>`
4. Получил результат → `<таблица>.status = 'done'`
5. Заплатил → `payments.status = 'succeeded'`

## 4. Здоровье продукта

| Что | Где смотреть | Что считаем тревогой |
|---|---|---|
| Ошибки приложения | <лог прода: команда/место> | больше N за сутки или новый тип |
| Фоновые задачи | <таблица очереди / лог воркера> | есть упавшие |
| Внешние API | лог вызовов провайдера | доля неуспешных > N% |
| Деньги | <где считается расход> | расход за период выше X ₽ |

| Среда | База | Логи | Доступ |
|---|---|---|---|

- Содержимое пользовательских текстов и файлов — не нужно для решений, а утечь может.
- Почту, имя, платёжные реквизиты в событиях — хватает идентификатора пользователя.
- <что ещё отказались собирать и почему>

```

---

## Как этим пользуется отчёт

`analytics-report` читает разделы 2–5: по ним он знает, **что** считать в этом продукте, **где**
это лежит и **как** дотянуться до боевой среды. Разделы 1 и 7 он использует, чтобы расставить
акценты и честно сказать, чего посчитать пока нельзя.
