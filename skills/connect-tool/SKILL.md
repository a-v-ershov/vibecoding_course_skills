# Connect Tool — один проект в Claude Code и Codex

## 📚 Объясни пользователю (перед началом, своими словами, 3–5 предложений)

Claude Code и Codex — два ИИ-агента, и спеку с задачами в `docs/` они читают одинаково. А вот
правила проекта и его мини-скиллы ищут в разных местах: Claude Code — в `CLAUDE.md`
и `.claude/skills/`, Codex — в `AGENTS.md` и `.agents/skills/`. Если проект начат в одном
инструменте, второй не увидит ни бюджета, ни правила одной ветки, ни правил безопасности —
и будет работать так, будто их нет. Этот скилл раскладывает общее так, чтобы оба видели одно и
то же: правила — в `AGENTS.md` (а `CLAUDE.md` просто ссылается на него), мини-скиллы — в общей
папке с симлинком. Код, спека и задачи не меняются.

## Порядок работы (скопируй чеклист в ответ и отмечай по ходу)

```
- [ ] 0. Разведка (только чтение): где мы, что есть в проекте, что видит каждый инструмент
- [ ] 1. Учебный блок: почему второй инструмент «не видит» проект
- [ ] 2. План — отдельным сообщением; жди одобрения
- [ ] 3. Правила: AGENTS.md + CLAUDE.md = @AGENTS.md
- [ ] 4. Правила, жившие только в памяти, → AGENTS.md
- [ ] 5. Мини-скиллы: настоящая копия в .agents/skills/ + симлинк в .claude/skills/
- [ ] 6. Плагин во втором инструменте: версия и команды
- [ ] 7. Проверка и коммит через /commit
- [ ] 8. Итог + «Что делать дальше»
```

Как каждый шаг выглядит в Claude Code и в Codex (вопросы, память, песочница Codex, схема
мини-скиллов) — `skills/_shared/platforms.md` этого плагина, разделы 3, 4, 6, 8 и 9. Прочитай
его до разведки.

### 0. Разведка — только чтение

Ничего не меняя, выясни:

- **Где ты** — в Claude Code или в Codex (вступление `platforms.md`), и куда переезжаем:
  аргумент `codex` / `claude`; пусто — готовим проект к обоим.
- **Файлы правил:** есть ли `AGENTS.md` и что в нём; `CLAUDE.md` — нет его, одна строка
  `@AGENTS.md` или в нём сами правила; есть ли в `CLAUDE.md` другие `@`-импорты (`@docs/…`) —
  Codex их не раскрывает. Личный `CLAUDE.local.md` и правила других инструментов
  (`.cursorrules` и подобные) не трогаются — только упомяни, что они есть.
- **Мини-скиллы:** все папки с `SKILL.md` в `.claude/skills/` и `.agents/skills/`. У каждого —
  настоящая папка, симлинк (`readlink`) или копия; одинаковые ли копии в двух местах (`diff -r`).
- **Работают ли симлинки:** ОС и `git config core.symlinks` (на Windows часто `false`).
- **Память:** если у текущего инструмента есть постоянная память по этому проекту — какие там
  правила проекта (типичное — «git только в ветке `main`», его записывал старый `init-project`).
- **Ключевые правила в `AGENTS.md`:** правило одной ветки, бюджет и ограничения по инструментам
  (раздел слоя 2 спеки, `skills/_shared/constraints.md` этого плагина), правила безопасности.
- **Плагин:** его версия — поле `version` в `.claude-plugin/plugin.json` или
  `.codex-plugin/plugin.json` в корне этого плагина; во втором инструменте — `claude plugin
  list` или `codex plugin list`, если эта команда есть на компьютере (только чтение). Нет —
  скажи человеку, как посмотреть самому.

Нет ни `AGENTS.md`, ни `CLAUDE.md`, ни мини-скиллов — проект не инициализирован, этот скилл
не для него: предложи `/init-project` и остановись.

### 1. Учебный блок

Своими словами — блок «📚» выше, с фактами разведки: что именно сейчас не увидит второй
инструмент («Codex не прочитает правила из `CLAUDE.md`: бюджет 0 ₽ и правило ветки `main`
для него не существуют»).

### 2. План — отдельным сообщением

Покажи план **отдельным сообщением, которым ход заканчивается**, и жди одобрения обычным
ответом человека. Каждый пункт — действие плюс одна строка обычным языком: зачем это. Два
списка: **«Сделаю сам»** (файлы правил, мини-скиллы, коммит) и **«Только ты»** (поставить
второй инструмент, поставить или обновить в нём плагин, разрешить Codex запись в `.git`
и `.agents/`). Уже готовое называй одной строкой «уже в порядке» — и не переделывай.

### 3. Правила: `AGENTS.md` + `CLAUDE.md` = `@AGENTS.md`

| Что нашла разведка | Что делаем |
|---|---|
| `AGENTS.md` с правилами, `CLAUDE.md` = `@AGENTS.md` | ничего — уже в порядке |
| только `CLAUDE.md` с правилами | содержимое **дословно** переносится в `AGENTS.md`, в `CLAUDE.md` остаётся одна строка `@AGENTS.md` — только с согласия человека |
| только `AGENTS.md` | создай `CLAUDE.md` из строки `@AGENTS.md`: Claude Code читает `AGENTS.md` и без него, но первый же `/init` в Claude создаст `CLAUDE.md`, и `AGENTS.md` читаться перестанет |
| оба с правилами | покажи списком, чего из `CLAUDE.md` нет в `AGENTS.md`; одобренное допиши в `AGENTS.md`, `CLAUDE.md` замени на `@AGENTS.md` |

- `@`-импорты из `CLAUDE.md` (`@docs/conventions.md`) переносятся в `AGENTS.md` обычной
  ссылкой словами: «Соглашения — в `docs/conventions.md`, прочитай перед работой».
- Строки, нужные только Claude Code (например, про его настройки или плагины), остаются
  в `CLAUDE.md` **после** строки `@AGENTS.md`.
- Человек против переноса → `CLAUDE.md` не трогай и прямо скажи, что Codex правил проекта
  не увидит. Дублировать правила в два файла не предлагай — копии разойдутся.

### 4. Правила, жившие только в памяти

Правило проекта, которое есть в памяти инструмента, но не в `AGENTS.md`, — допиши в раздел
«Правила» `AGENTS.md`: второй инструмент чужой памяти не видит. Доступа к памяти нет —
проверь по разведке, что в `AGENTS.md` есть три ключевых правила; недостающее предложи
дописать: бюджет — из раздела слоя 2 спеки (формат — `skills/_shared/constraints.md` этого
плагина), ветку и безопасность — по шаблону №2 `skills/init-project/references/templates.md`
этого плагина. Ничего не выдумывай сверх спеки и шаблона.

### 5. Мини-скиллы

Схема — раздел 4 `platforms.md`: настоящий скилл в `.agents/skills/<имя>/`, в
`.claude/skills/<имя>` — симлинк на него. По каждому мини-скиллу:

| Что нашла разведка | Что делаем |
|---|---|
| только в `.claude/skills/<имя>` (настоящая папка) | `git mv` в `.agents/skills/<имя>`, на старом месте — симлинк `../../.agents/skills/<имя>` |
| только в `.agents/skills/<имя>` | симлинк в `.claude/skills/<имя>` |
| настоящие копии в обеих папках, одинаковые | оставь `.agents/`, в `.claude/` — симлинк вместо копии |
| настоящие копии в обеих, разные | покажи разницу человеку и спроси закрытым вопросом, какую оставить; другую не удаляй без ответа |
| уже симлинк по схеме | ничего |

- Симлинки недоступны → копия в обе папки и строка в `AGENTS.md` «мини-скиллы продублированы
  в `.agents/skills/` и `.claude/skills/` — правь обе копии».
- В Codex запись в `.agents/` и коммит требуют разрешения выйти из песочницы — раздел 8
  `platforms.md`.
- Трогаются только папки скиллов: настройки (`.claude/settings*.json`, `.codex/`), агенты
  и прочие файлы инструментов остаются как есть.

### 6. Плагин во втором инструменте

Версии плагина в двух инструментах должны совпадать: старый плагин (до 0.8) снова начнёт
писать правила в `CLAUDE.md` и мини-скиллы только в `.claude/skills/`. Ставит и обновляет
человек сам — это глобальная установка на компьютер. Дай команды для нужного инструмента:

| | Поставить | Обновить |
|---|---|---|
| **Claude Code** | `/plugin marketplace add a-v-ershov/vibecoding_course_skills`, затем `/plugin install vibecoding-course@vibecoding-course` | `/plugin marketplace update vibecoding-course`, затем `/plugin update vibecoding-course@vibecoding-course` |
| **Codex** | `codex plugin marketplace add a-v-ershov/vibecoding_course_skills`, затем `codex plugin add vibecoding-course@vibecoding-course` | `codex plugin marketplace upgrade vibecoding-course`, затем `codex plugin add vibecoding-course@vibecoding-course` (без второй команды остаётся старая версия) |

После установки — перезапустить инструмент. Скиллы в Codex вызываются как
`$vibecoding-course:<скилл>`, в Claude Code — `/vibecoding-course:<скилл>`.

### 7. Проверка и коммит

- `CLAUDE.md` — ровно `@AGENTS.md` (плюс одобренные строки только для Claude), `AGENTS.md`
  содержит правила.
- Каждый мини-скилл читается по обоим путям (`cat .claude/skills/<имя>/SKILL.md` через
  симлинк), `git status` показывает симлинки как файлы-ссылки, а не пропажу.
- В диффе — только файлы правил и папки скиллов; код, спека и задачи не тронуты.
- Коммит — через скилл `/commit` (сообщение на английском, в `main`).

«Файлы созданы» — не проверка; проверка — прочитанный через симлинк скилл и чистый дифф.

### 8. Итог

По общему формату (`skills/_shared/report-format.md` этого плагина): первой строкой — готов ли
проект ко второму инструменту; затем что перенесено и что уже было в порядке; что осталось
человеку (поставить или обновить плагин, перезапустить инструмент); в конце «Что делать
дальше» — например, открыть проект во втором инструменте и попросить его перечислить скиллы
проекта: мини-скиллы должны быть в списке.

## Правила

- **Ничего не затирай.** Перенос из `CLAUDE.md` в `AGENTS.md` — только с согласия и дословно;
  расходящиеся копии мини-скиллов — только с ответом человека, какую оставить.
- **Код продукта, спека, задачи и настройки инструментов не трогаются** — только файлы правил
  и папки мини-скиллов.
- **Глобальное — руками человека или с явного «да».** Второй инструмент и плагин в нём ставит
  человек; скилл даёт точные команды.
- **Перезапуск безопасен:** готовое пропускается, повторный прогон на готовом проекте —
  отчёт «всё в порядке» без изменений.
- Работа идёт в одной ветке `main`, новых веток не создаём.
- Объясняй незнакомое одной строкой (симлинк, `@`-импорт, песочница) — аудитория часто
  не программисты.
- **Финальный отчёт — по общему формату** (`skills/_shared/report-format.md` этого плагина):
  первой строкой итог, в конце — блок «Что делать дальше».

## Язык

Отвечай и спрашивай на языке пользователя; определять не по чему (скилл вызван без текста) —
по умолчанию русский. Код, идентификаторы и пути не переводятся; сообщения коммитов — на
английском.
