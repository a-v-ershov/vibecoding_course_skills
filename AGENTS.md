# AGENTS.md

Правила работы с этим репозиторием — для любого ИИ-агента (Codex читает этот файл
напрямую, Claude Code — через `CLAUDE.md`, где одна строка `@AGENTS.md`).

Репозиторий плагина `vibecoding-course` для Claude Code и OpenAI Codex (одна версия на оба
инструмента): 32 скилла курса по вайб-кодингу (`skills/`, плюс общие справочники
в `skills/_shared/`: формат задач `task-format.md`, правило бюджета `constraints.md`, формат
финального отчёта `report-format.md` и различия инструментов `platforms.md`), четыре агента
(`agents/`: критик спеки, скептик ИИ-идей, исполнитель задачи, независимый тестировщик),
манифесты плагина и маркетплейса для Claude Code (`.claude-plugin/`) и для Codex
(`.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`).

## Правила скиллов

- **Инструменты подбираются по бюджету человека.** Общее правило и формат декларации
  ограничений — `skills/_shared/constraints.md`; скилл, который что-то выбирает
  (площадку, модель, сервис, UI-кит), читает раздел «Бюджет и ограничения по
  инструментам» слоя 2 спеки и идёт снизу вверх: уже оплаченное → постоянно
  бесплатное → дешёвое → платное.
- **Скиллы переносимы между проектами.** Ничего специфичного для конкретного
  репозитория (домен продукта, его таблицы, его внешние API) в них не попадает:
  стек, команды и сущности скилл определяет из файлов проекта, куда его позвали.
- **Пути внутри плагина** — `skills/_shared/task-format.md` и `agents/<имя>.md`
  «этого плагина», а не `.claude/skills/…`: в установленном плагине их там нет.
- **Скиллы и агенты пишутся нейтрально к инструменту.** Никаких `AskUserQuestion`,
  `subagent_type`, «памяти Claude» в тексте скилла: пишем «запусти агента `X`», «задай
  закрытым вопросом с вариантами», «`AGENTS.md` проекта», «мини-скилл в `.claude/skills/`
  или `.agents/skills/`». Как это выглядит в Claude Code и в Codex — только
  в `skills/_shared/platforms.md`; новая специфика инструмента дописывается туда же.
- **`description` скилла — не длиннее 1024 символов** (лимит стандарта Agent Skills). В описании — когда звать и что получится; механика,
  пороги и правила — в теле `SKILL.md`. Codex показывает модели только первые ~320 символов
  описания, поэтому «что делает и когда звать» — в самом начале.
- **Тело `SKILL.md` — не длиннее ~12 000 символов** (≈ 5000 токенов: столько рекомендует
  стандарт Agent Skills, и столько Claude Code сохраняет от скилла после сжатия контекста).
  Шаги, решения и правила, которые должны работать всегда, — в `SKILL.md`; шаблоны, большие
  таблицы и каталоги — в `references/` скилла, со строкой в `SKILL.md`, когда их читать.
- **У каждого скилла есть `agents/openai.yaml`** — `display_name` и `short_description`
  на русском для интерфейса Codex (Claude Code этот файл не читает). Новый скилл — новый файл.
- **Ограничения агента дублируются словами в его теле.** Поле `tools:` во frontmatter
  применяет только Claude Code; в Codex агент работает по тексту файла.

## Проверка перед коммитом

- **Claude Code:** `claude plugin validate .` — должно быть «Validation passed». Предупреждения
  про иконку, `LICENSE` и `CLAUDE.md` в корне известны и не мешают.
- **Codex:** отдельной команды проверки плагина нет. Скиллы проверяет валидатор встроенного
  скилла `skill-creator`: `python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py
  skills/<скилл>` (нужен PyYAML). Ожидаемо ругается только на `argument-hint` — поле оставлено
  сознательно: его показывает меню `/` в Claude Code, а Codex скиллы с ним загружает. Любое
  другое замечание (угловые скобки `<` `>` в `description`, длина, имя) — исправлять.
- **Загрузка в Codex:** `codex plugin add vibecoding-course@vibecoding-course` с локальным
  маркетплейсом и `codex debug prompt-input` — в списке должны быть все скиллы плагина.

## Версии и манифесты

- **Поднимается только версия плагина** — `version` в `.claude-plugin/plugin.json`
  и `.codex-plugin/plugin.json`, всегда вместе и на одно и то же число. По ней у
  пользователей обновляется установленный плагин.
- **`metadata.version` в `marketplace.json` — версия каталога маркетплейса, а не
  плагина.** Не поднимать её без моей явной просьбы, даже «для синхронности»:
  на обновление плагина она не влияет, и совпадать эти числа не обязаны.
- Описания (`description`) во всех манифестах правятся по факту: изменился состав
  скиллов — обновляем текст, это не версия.
